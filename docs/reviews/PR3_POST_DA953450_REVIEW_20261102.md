## Findings on the delta

1. **The source-byte gate works, but the published stats were not regenerated through it (medium, reproducibility).**
   The gate hashes the 3 frozen eval inputs against the pinned `9e4d4df8…` leaves before it writes. Because the root is
   compared with a constant, a forged bundle fails. A duplicate-last leaf (A1) can only copy the edges leaf, so it can't
   swap an input hash. But `evidence/stats/discovery_audit.json` is unchanged in this delta and has no
   `source_byte_verification` field. The committed numbers (25/38 vs 27/38, p = 0.6875) therefore come from the
   ungated exporter. They match PR #11's independent recount, so I don't think they're wrong, but the receipt doesn't prove that the gate ran.
   Fix: rerun the exporter on the Mac that holds the private sources and commit the new receipt as a successor.
2. **`freeze_review_export.py` hard-codes the parent (low, correctness).** `parent_project_root` and
   `parent_repo_commit` are literals (now `2f1cfafd…` / `da953450`). The next run will misdeclare its parent
   unless someone edits them by hand, which is how the stale `513cb1f8…` value got there before.
   `execute_notebooks.py` does the same with `predecessor_run`. Fix: derive both from the newest successor and `git rev-parse HEAD`.
3. **The new successor was verified against current files, not a pinned commit (F-02 recurrence, fixed on main).** At `da51622`,
   `REVIEW-90761061` wasn't in `HISTORICAL_COMMITS`, so the first edit to any leaf file broke CI. `675e619` pinned it.
   Every future successor needs the same pin in the commit that creates it.
4. **Teammate importer (`import_fhir.py`), already in the gap ledger.** It uses `uuid4()` source and fact ids, delete-then-reinsert,
   and ordinal `SYN-xxxxx` ids, so a re-import isn't byte-reproducible and ids can change referents. I agree with the ledger's P0. This is a note, not a block.
5. **Leakage: none found.** I ran a regex scan of every added line for DSNs with passwords, JWTs, Supabase keys, AWS and GitHub tokens, and
   PEM blocks. It found only placeholders (`DB_USER:DB_PASSWORD@YOUR_POOLER_HOST`). `.gitignore` covers `.env`, `.env.*` and `.env.local`.
   The delta adds no binaries or parquet files. I couldn't run gitleaks in this container: the binary isn't installed, and downloading it was refused.
   The helper doc says the DB password was shared over Discord. Rotate it, as the doc says.
